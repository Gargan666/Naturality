NATURALITY - RESOURCE DROP FOLDER
================================

Put finished assets here. Ctrl+Shift+B in VS Code (or gradlew build)
automatically packages them in the mod JAR under assets/naturality/.
The development client and VS Code debug resource task use this folder too.
Do not copy files into build/ or duplicate them under src/main/resources.

WHERE FILES GO
  textures/block/     Block textures (.png)
  textures/item/      Item textures (.png)
  textures/entity/    Entity textures (.png)
  textures/particle/  Particle textures (.png)
  textures/gui/       Interface textures (.png)
  sounds/            Audio clips (.ogg, encoded as Ogg Vorbis)
  sounds.json        Sound events and the clips each event plays

Use lowercase filenames with underscores, without spaces. Subfolders are OK.
Keep editable source files (PSD, Aseprite, WAV masters, etc.) elsewhere.
README.txt and .gitkeep files are excluded from the build.

TEXTURES
Use PNG. Ordinary block/item textures commonly start at 16 x 16 pixels.
Animation metadata can sit beside its PNG as filename.png.mcmeta.
Example: resources/textures/block/mossy_stone.png
  JAR: assets/naturality/textures/block/mossy_stone.png
  Model reference: naturality:block/mossy_stone
Adding a texture alone does not register a new block, item or particle.

ENCHANTMENT MENU
Edit textures/gui/enchanting.png to replace the open-book menu artwork.
This is a 320 x 276 RGBA image, drawn at one texture pixel per GUI pixel.
It includes the book, player inventory panel and slot backgrounds, without text,
buttons or items. Transparent pixels reveal the world behind the menu.
The existing resource copy packages it as assets/naturality/textures/gui/enchanting.png.
Keep its canvas size and slot positions when repainting:
  Item/lapis: (221,136), (241,136), each 16 x 16.
  Item is at the bottom center of the right page; lapis is immediately to its right.
  Slot artwork includes a one-pixel border around those coordinates.
  Inventory: (80,192), 9 columns and 3 rows, spaced 18 pixels apart.
  Hotbar: (80,250), 9 columns spaced 18 pixels apart.
  Left-page buttons end at (20,140), width 124 and height 20, filling upward
  at 22-pixel spacing as more buttons become visible.
Build to copy edits into the development resources, then reload with F3+T.
The background is not regenerated by builds; your artwork remains authoritative.

ENCHANTMENT LIBRARY MENU

in textures/gui/: 144 x 178 pixels, displayed at 106 x 94 GUI pixels. It starts
at (-36,182) relative to the main book. Editing library art does not affect it.

stays until the next puzzle's typewriter presentation completes.
enchanting_library_empty.png is the separate empty-library message panel, drawn
at its native 132 x 66 size at library (6,24), without stretching. The default
font wraps the message to six 9-pixel lines with 6 pixels of padding per side.
Library rows select enchanting_library_row_1.png (long), _2.png (medium), or
_3.png (short) from the widest displayed name. Each canvas stays 128 x 30;
the artwork occupies widths 128, 96, and 80 respectively. Names have 109, 77,
and 61 pixels of space. Both names count for paired entries.
enchanting_library.png includes solid icon-position markers: cyan for single
entries, pink/orange for paired entries. Cyan covers their overlapping pixels.
Additional solid markers on that PNG:
  Blue: row backgrounds, (8,24 + 34*row), 128 x 30, four rows.
  Red: previous/next buttons, (8,160) and (116,160), 20 x 14.
  Yellow inside buttons: centered arrow-label area, 6 x 9.
  Purple: heading area (8,9), 128 x 9; centered page-counter reserve (52,163), 40 x 9.
  Yellow in rows: single name, (24,rowY+11), 109 x 9.
  Green/light green: paired names, (24,rowY+4) and (24,rowY+18), 109 x 9.
  Single-name yellow covers overlapping paired-name pixels.
Text boxes indicate available space, not the width of a particular name. The
page counter's actual width varies and remains centered at x=72. Empty-library
text starts at (8,30), wraps at 128 pixels, and replaces the rows in that state.
enchanting_library_layout.svg in textures/gui/ overlays exact icon guides on the
panel and row textures: cyan for single entries, pink for enchantment/curse pairs.
All icons are 10 x 10. Relative to each row: single (3,10), paired (3,3) and (3,17).
Relative to the panel: x=11; single y=34,68,102,136; paired y=27/41,61/75,95/109,129/143.
The SVG is an editable art reference; the game continues to use the PNG textures.
The Library bookmark opens a panel to the left of the main book. Its placeholder
textures are simple bordered boxes in the same textures/gui/ directory:
  enchanting_library.png           144 x 178, panel background.
  enchanting_library_tab.png        24 x 32, closed bookmark.
  enchanting_library_tab_open.png   24 x 32, open bookmark.
  enchanting_library_row.png       128 x 30, one selectable book row.
Keep these canvas sizes when replacing the placeholders. The bookmark begins at
(20,-20) relative to the main book and extends 12 pixels underneath its page area.
The panel begins at (-144,0). Four rows start at panel (8,24), spaced 34 pixels;
the heading is horizontally centered at x=72 with its top at y=12, and page controls are at y=160. Labels/icons are drawn by
the menu; do not bake them into the artwork. Arrow buttons use the vanilla GUI.
The book and library are centered together while open. Mouse wheel and arrows page
through the collection; hovering a row shows the source book's full tooltip.
These files are packaged directly and never regenerated by a build.

Library books must be deciphered and stored in chiseled bookshelves at the normal
enchanting bookshelf positions (two blocks out, table height or one block above),
with the usual clear gap. Populated chiseled shelves also count toward the 15-shelf
starting-quality limit. Every eligible shelf slot appears; encrypted books do not.
Select an entry with an eligible item in Item. Enchanted books in Item enter book deciphering mode.
Survival entries reuse their exact enchantment, optional curse and levels; creative
entries reuse their single enchantment or curse. The shelf book is never consumed.
Selections start deciphering, then require the usual lapis-funded writing attempt.
They may replace an untouched, curse-free puzzle or begin after completion.
A progressed/deciphered/writing/Empower attempt cannot be overwritten. Close/reopen
retains the selected offer, puzzle and revealed letters while the item stays in the table.
Removing the item clears this pending work. Empty slots show vanilla sword/lapis
sprites instead of Item/Lapis labels. Deciphering
failures retain the offer, add or strengthen its curse, and automatically retry
for free. The server rechecks shelf access and contents at selection time.

The deciphering page uses the vanilla alt font in a 20 by 13 character grid at
book (20,36), with 6 by 9 pixel cells. Its clue/attempt tab reuses
enchanting_library.png scaled to 70 by 94 at (0,182), beside the inventory.
The Submit button is at (4,254), size 62 by 16. Text and selection highlights are
dynamic; the existing main book texture is unchanged. Successful enchantment
details occupy the left page. Actions are bottom-aligned on the right page at
y=96, stepping upward by 22 pixels, above the material slots. Empower uses a fresh
deciphering puzzle. The Inventory, Quality and Progress labels are hidden.

ENCHANTMENT ICONS
Put 16 x 16 PNG icons in textures/misc/enchantment/icons/.
The filename is the enchantment's registry name, with a trailing _curse removed:
  minecraft:mending -> mending.png
  minecraft:binding_curse -> binding.png
  naturality:fragility_curse -> fragility.png
Books, the enchanting table and tooltip icons all use this lookup automatically.
Missing icons and encrypted entries use missing.png. No model/font JSON is needed.
For names shared by multiple mods, namespace subfolders take priority, for example
icons/minecraft/mending.png. A mod can also supply the same texture path in its
own asset namespace. Build to copy changed inputs into the development resources;
F3+T reloads the packaged textures and discovers added icons without code changes.
Descriptions use enchantment.<namespace>.<registry_name>.desc language entries;
see ENCHANTMENT DESCRIPTIONS below to edit the wording and dynamic values.
Use the _curse suffix for all new Naturality curse registry IDs; do not rename
external mods' registries. The old naturality:fragility data entry exists only to
load and migrate saved items; new books and offers use naturality:fragility_curse.

ENCHANTMENT DESCRIPTIONS
Write descriptions in src/client/resources/assets/naturality/lang/en_us.json.
Edit the entries ending in .desc; keep each key and change its quoted text.
Other languages can provide the same keys in their corresponding language file.
Plain text works as before. Put arithmetic formulas inside braces to calculate values.
The only variable is level: the actual enchantment level, including stacked curses.
  {level}                 Display the level itself.
  {25 * level}            Multiply the level by 25; x and Ã— also mean multiplication.
  {10 + 5 * (level - 1)}  Use addition, subtraction and parentheses.
  {level / 2}             Divide; decimal numbers such as 0.5 are also supported.
Multiplication/division happen before addition/subtraction; parentheses override this.
Unary signs are allowed, for example {-level + 5}. Variable names are case-sensitive.
Example:
  "enchantment.naturality.fragility_curse.desc": "Durability loss +{25 * level}%"
This shows +25% at level I, +75% at level III and +125% at level V.
Formulas only control the displayed text; keep them consistent with gameplay balance.
Use any number of formulas in a description; percent signs outside braces are plain text.
Results round to at most six decimal places, with no trailing zeros (1 / 3 -> 0.333333).
Invalid formulas, unknown variables and division by zero remain literal for easy editing.
Each formula is limited to 256 characters. Functions, powers and scripts are unsupported.
The old max_level and durability_loss_percent placeholders have been replaced by formulas.
Build after editing the source language file, then reload resources with F3+T.
Builds do not regenerate descriptions, and encrypted books keep them obscured.

SOUNDS
Export as Ogg Vorbis (.ogg), not Ogg Opus. Renaming an MP3/WAV is not conversion.
Use MONO for sounds located in the world, so positioning and distance fading
work correctly. Stereo is suitable for non-positional music/UI ambience.
44.1 kHz or 48 kHz are practical export sample rates.

Example: resources/sounds/portal/open.ogg
  JAR: assets/naturality/sounds/portal/open.ogg
  Sound file reference: naturality:portal/open (no sounds/ prefix or .ogg)

TO REPLACE THE EXISTING PORTAL OPENING SOUND
1. Create sounds/portal/ and put your mono open.ogg there.
2. In resources/sounds.json, replace the portal_open sounds array with:
     "sounds": [ { "name": "naturality:portal/open", "type": "file" } ]
3. Keep its subtitle and event name. Build and restart the development client.
The existing definition uses Minecraft's End portal sound until you change it.

New events can be added as additional entries in sounds.json, but the mod must
also call those events to play them; dropping an audio file here does not make
it play automatically. Other resource JSON files remain in src/main/resources.

See AGENTS.md in the project root for the current project map and working rules.

CHORUS FLOWER MODEL
Edit block models/chorus_flower_bloom.json in this folder. Each build and
Gradle development launch generates assets/naturality/models/block/chorus_flower_bloom.json
from that export. VS Code's prepare debug resources task does this too.
The build remaps resources: texture references to naturality:, repairs the
export's unresolved particle alias and omits unassigned #missing faces.
Both vanilla living/dead flower model overrides inherit the generated model.
After editing, rebuild/relaunch; F3+T alone does not run the build conversion.
Both chorus_flower.json and chorus_flower_bloom.json exports are now imported
automatically. Placed flowers choose normal/bloom at weights 9:1 across all ages;
the inventory item uses the normal model. Edit either export and rebuild/relaunch.
Chorus flowers now store facing and bloom in their game block state. New flowers
roll bloom once at 10%; that saved choice controls both the model and hitbox.
The earlier render-only 9:1 weighted blockstate has been replaced. All six model
orientations are mapped automatically through blockstate rotation; model export
edits still require rebuild/relaunch. Normal collision is 7/16 block along facing;
decorative leaf/hair planes do not collide.
Edit textures/block/chorus_plant.png to change the plant texture across vanilla
stems and custom flower models. The build maps this single source to both
minecraft and naturality texture namespaces, including optional PNG animation
metadata. Rebuild/relaunch after editing. Growing flowers and branches now
inherit their parent's normal/bloom variant; growth does not reroll it.
